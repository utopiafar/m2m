# 08 路线图与成本

工时按**AI Coding 口径**：一位开发者主导，Coding Agent 能在真机上构建、读取日志、运行测试。**表中小时是开发者需要投入的设计、审查、联调、验收时间；Agent 在旁边运行的时间不重复累加。** 这是"有效投入"而非"人月"。

## 0. 估算前提

- 两台 Apple Silicon Mac，先统一系统版本（P7）。
- 首版支持 Claude 及少量常见应用，**1–3 个主要窗口**。
- 复用现有采集与通信能力；**不自研编码器、虚拟显示驱动或完整 RDP**。
- 已有两台 Mac，无新增硬件费。

## 1. 里程碑

### M0 — 验证原型与门槛（必须先做，不可跳过）

**目标**：用最小闭环回答 G1/G2/G3/G4 四个问题，其中窗口、缩放、文本输入是核心假设。

| 验证 | 通过标准 |
|---|---|
| 独立窗口 | 远端主窗口在本地单独出现，能与本地应用混排，不显示远端桌面 |
| 真实缩放 | 改变本地大小后远端重新排版；松手后文字恢复清晰（非永久缩放旧画面） |
| 基本交互 | 中文、快捷键、滚动、设置或菜单能完成一次连续使用流程 |
| 安全恢复 | 断线后远端应用保留；重连不重放旧输入、不残留修饰键、不写错窗口 |
| 文本闭环（G1） | caret rect 可获得；候选窗贴近插入点；**选词 Enter 不误发送** |

**预算：8–16 小时有效投入（约 1–3 个开发日）。**

**先做测试 App。** 先用 `TestApp-Native` / `TestApp-Electron` 排查通用远控问题，再用 Claude 做兼容性测试——只拿 Claude 当测试对象，很多失败很难归因，Agent 会反复猜。

#### M0 的具体执行顺序

| 步骤 | 产出 |
|---|---|
| 1. 写 `TestApp-Native`（含可断言的状态读取接口） | 一个可控、可自动断言的 GUI 测试对象 |
| 2. Host 侧：窗口枚举 + 单窗口采集 + 编码，先跑通局域网 | 能采到画面 |
| 3. Viewer 侧：独立 `NSWindow` + 解码显示 | 看到远端窗口成为本地窗口 |
| 4. 尺寸同步（请求 → 远端 AX 改尺寸 → 读回 → 客户端切换清晰画面） | 缩放正确性的证明 |
| 5. 输入桥：鼠标、键盘、**最小可用的本地中文输入 + TextCommit** | G1 首次结果 |
| 6. 断线恢复基础用例 | G4 首次结果 |
| 7. 换成真实 Claude 复测 | 兼容性结论 |

### M1 — 自用第一版

| 工作项 | 主要工作 | 有效投入估计 |
|---|---|---:|
| 宿主启动与现有代码验证 | 编译、权限、窗口枚举、确认采集与输入可用 | 6–10 h |
| 原生 Mac 客户端 | 窗口创建、视频显示、连接状态 | 8–14 h |
| 窗口尺寸与 Retina | 几何映射、尺寸读回、缩放结束恢复清晰 | 6–12 h |
| 输入桥 | 鼠标、滚动、快捷键、**完整中文输入桥** | 8–14 h |
| 多窗口与常见弹窗 | 设置、菜单、面板、焦点与父子关系 | 6–12 h |
| 安全与跨网连接 | 配对、加密、中继、断线恢复 | 8–14 h |
| 基础剪贴板与文件桥接 | 文本/图片、文件上传与回传 | 4–8 h |
| 诊断、打包、回归 | 日志、指标、安装、基础可靠性测试 | 6–12 h |
| **合计** | | **52–96 h** |

> 与原调研的 **50–100 小时**预算一致（本表按工作项重新加总，上限取 96 h）。

**若对 AppKit、macOS 权限与媒体链路都不熟悉，另外预留 20–40 小时学习与排障预算。** 这是个人技术栈带来的变量，不是编码量本身。

### M2 / M3 — 稳定自用版与对外测试版

| 完成度 | 能证明/交付什么 | 累计投入 | 折合开发日（约 6 h/日） |
|---|---|---:|---:|
| **验证原型（M0）** | 一个独立本地窗口，能显示、点击、输入、缩放远端应用 | 8–16 h | 1–3 |
| **自用第一版（M1）** | 常见操作、中文、基础文件、多窗口与安全连接 | 50–100 h | 9–17 |
| **稳定自用版（M2）** | 较充分的跨网、长时间运行、恢复与应用兼容性验证 | 100–180 h | 17–30 |
| **对外测试版（M3）** | 安装升级、权限引导、设备差异、错误恢复、诊断支持 | 200–350 h | 34–59 |

**这些是累计投入，不是逐行相加。**

### 里程碑的硬门禁

- **M1 不得在 G1 未通过时启动。** 若 G1 显示需要 Claude 专用适配器，应在 M0 内追加该项预算后再评估。
- **M2 不得跳过弱网矩阵**（`06` §4）。
- **M3 不得在 P9（分发方式与许可证）未定案时启动**，因为复制/分发会触发不同的许可证义务。

## 2. 成本

### 2.1 软件与基础设施

| 项目 | 价格/口径 | 说明 |
|---|---:|---|
| 参考实现源码 | 无源码购买费 | 但许可证约束需分别评估，见 `10-risks-licenses.md` |
| 个人原型中继 VPS | **$6–12/月**起 | 普通云服务器价格，**不构成跨境低延迟保证** |
| BetterDisplay Pro（可选） | **$21.99** | 用于先解决专用虚拟显示器，避免首版自研这部分 |
| Apple Developer Program（可选） | **$99/年** | 本机开发测试不要求先付；准备正式签名分发时再考虑 |
| AI 开发用量 | **$100–300 项目预算** | **这是预算假设，不是平台报价或用量预测**；已有订阅额度可能覆盖一部分 |
| 远端 Mac | 单独计算 | 已有机器则无新增购买费；家庭托管、电力、维护无统一价格 |

### 2.2 硬件租赁参照（非本方案推荐）

MacStadium 当前列出 M4 16GB 独享 Mac 为 **$149/月**。**但它是机房托管，不是家庭环境，不能与本方案的最初设想的家庭主机等同。**

### 2.3 流量

见 `05-media-performance.md` §10。要点：

- 单人使用**不天然需要昂贵中继**；入站通常免费，出站按额度计费，不能把"经过服务器的一进一出"都算成收费出站。
- 以 8 Mbps 场景（约 380 GB/月）为例，若使用 LiveKit Cloud Ship 方案（**$50/月含 250 GB 下行，超出 $0.12/GB**），基础费加流量约 **$66/月**；两端合计约 10,560 连接分钟，仍在其公开的 150,000 分钟额度内。
- **取舍：个人单会话先测试自建中继；需要省运维、快速比较多地区连接时，再考虑托管。**

## 3. AI 能压缩什么、不能省掉什么

| 最容易压缩 | 最难直接压缩 |
|---|---|
| 协议结构、窗口壳、序列化、状态机、测试代码、日志工具、安装脚本 | 在真实系统上找出"某个菜单为什么没出现""窗口缩放后为什么点偏""某种输入法为什么重复提交" |

**并行分工建议**：宿主 / 客户端 / 测试三条线；**但同一时刻只允许一个测试执行者控制同一个 Mac 图形会话**，否则多个 Agent 抢焦点会制造大量假故障。

## 4. 风险对预算的影响

| 若发生 | 影响 |
|---|---|
| G1 显示 Claude 需要专用适配器 | M0 追加预算；M1 视适配复杂度上调 |
| G2 显示必须改用图集方案 | 媒体链路重做一部分，M1 上限上调 |
| G3 显示 WebRTC 构建不达标 | 需要按 §5 的分阶段替换策略增加调优投入 |
| Claude 版本更新破坏适配 | 每次版本升级需跑全量 T-CN/T-WIN（`06` §7），属于持续成本 |

**第一轮若发现 Claude 的特殊窗口或输入行为不兼容，应根据实测重新估，而不是继续假设能按原预算完成。**

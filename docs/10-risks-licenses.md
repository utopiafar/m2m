# 10 风险登记与许可证边界

## 1. 风险登记

| 编号 | 风险 | 概率 | 影响 | 缓解措施 | 触发后的动作 |
|---|---|---|---|---|---|
| **R1** | Claude 不提供可用的插入点（caret rect），中文候选窗只能靠"最后点击位置" | 中 | 高（直接决定 P2 能否达标） | G1 优先验证；预留 Claude 专用适配器预算 | 按 P2 规则把 Claude 标为降级，或追加专用适配器后再评 |
| **R2** | Claude（Electron）的 AX 树对 `contenteditable` 覆盖不足 | 中 | 高（影响文本桥全部路径） | 先排除权限/启用状态（`AXManualAccessibility`），再判定；预留 CDP `imeSetComposition` 研究入口（不暴露公网） | 开发 Claude 专用适配器 |
| **R3** | 缩放后"真实重排 + 恢复清晰"无法稳定实现 | 中低 | 高（核心体验） | T6 定为正确性要求；M0 第 4 步专门验证 | 若无法达成，需要重新定义产品主张，而不是标注"部分支持" |
| **R4** | WebRTC 在跨境线路上排队/抖动导致延迟累积 | 中 | 中高 | 有界队列 + 输入优先 + 关键帧策略；G3 分层测量 | 定位到具体环节后再替换该环节，**不整体重写传输层** |
| **R5** | 应用更新破坏适配（Claude 版本升级） | **高（长期必然）** | 中 | 版本升级后跑全量 T-CN/T-WIN；适配器与通用链路解耦 | 修适配器，不改通用层 |
| **R6** | 远端无人值守时系统进入锁屏/休眠导致会话中断 | 高 | 中 | P6 明确一期只保证已登录会话内；文档与 UI 都不得过度承诺 | 若确实需要，二期单独立项 |
| **R7** | 许可证冲突导致复用代码不可分发 | 中 | 中（影响 P9） | 见 §2；先确认边界再决定 fork 或参考 | 更换实现路线或改为仅在自用范围内使用 |
| **R8** | 多 Agent 并行测试互相抢焦点产生假故障 | 中 | 低（浪费时间） | 硬性单执行者约束（`09` §4） | 加测试锁/租约 |
| **R9** | "窗口级共享 ≠ 键盘沙箱"被误当成安全边界 | 中 | 中（认知风险） | 写进产品定义（`07` §P 段末）；文档与 UI 一致表述 | 修正宣传口径 |
| **R10** | 中转服务器成本/合规问题 | 低 | 低 | 自建优先；E2EE；中继不承载业务内容 | 换服务商或换区域 |
| **R11** | 权限（屏幕录制/辅助功能）在远端被系统更新重置 | 中 | 中 | 权限自检 + 明确错误呈现（不静默失败） | 引导重新授权 |

### 概率/影响最高的三项

**R5（应用更新破坏适配）是唯一"必然发生"的风险。** 因此架构上必须保证：适配器是薄层，通用链路不因某个应用的特殊行为而被污染。

**R1/R2 是 M0 的核心待答问题**，它们的答案决定项目是否需要额外的专用适配器预算。

## 2. 许可证边界（P9 相关）

| 项目 | 许可证 | 含义 |
|---|---|---|
| **RustDesk** | AGPL-3.0 | 直接复用与分发需评估；不能当作可随意嵌入闭源产品的组件 |
| **Hopp** | AGPL-3.0 | 同上；其输入事件→控制器→系统这一层值得**参考设计** |
| **LiveKit Swift SDK** | Apache-2.0 | 相对宽松；仍需注意其服务端组件与部署方式的独立约束 |
| **Tailscreen** | MIT | 许可证宽松（可用于媒体链路、加密网络、丢包恢复、控制撤销的**参考或复用**） |
| **Transom** | AGPL-3.0 | 参考窗口管理设计；整仓 fork 需评估义务 |
| **FreeRDP** | Apache-2.0 | 适合研究协议与通道设计 |
| **MirageKit** | PolyForm Shield（**限制竞品**）+ 已归档 | **不能按普通宽松开源库选为产品依赖** |
| **ax-cli** | 需核对仓库 LICENSE | 工具用途，可用于验证控件可读性 |
| **Sinter** | 需核对仓库 LICENSE | 仅作控件模型的设计参考（本项目不走该路线） |

### 使用原则

1. **"参考设计"与"复用代码"必须严格区分**，并在报告与文档中写明（`09` §5）。
2. **有商业化可能就先选许可证边界清楚的依赖，不要先整仓 fork 再处理**（P9 锁定值）。
3. **允许"先自用验证、后处理许可证"** —— 但这必须是一个明确的决定，而不是默认状态。若最终要分发，AGPL 类依赖会限制你的发行方式。

## 3. 第三方能力清单（可复用 vs 仅参考）

| 能力 | 建议来源 | 用法 |
|---|---|---|
| 窗口采集 | **Apple ScreenCaptureKit** | 直接用 |
| 硬件编解码 | **Apple VideoToolbox** | 直接用 |
| 本地窗口与输入法 | **AppKit（NSWindow / NSTextInputClient）** | 直接用 |
| 实时传输 | **原生 WebRTC（含 TURN）** | 直接用；固定版本并验证 |
| 加密网络 / 丢包恢复 / 控制撤销 | **Tailscreen（MIT）** | 参考或受限复用 |
| RDP 通道与 RemoteApp 语义 | **FreeRDP（Apache-2.0）/ 微软公开规范** | 仅参考设计 |
| Swift 客户端呈现（VideoToolbox 解码、Metal 合成、指标） | **RDPKit（需核对 LICENSE）** | 参考 |
| 输入事件 → 控制器 → 系统 分层 | **Hopp（AGPL）** | 仅参考 |
| 窗口枚举 / 真实尺寸同步 / 图集采集 | **Transom（AGPL）** | 仅参考 |
| 中文输入法桥的历史先例 | **Sinter / 微软 MS-RDPETXT** | 仅参考 |

### 明确不采用

| 项目 | 原因 |
|---|---|
| MirageKit | 已归档 + PolyForm Shield 限制竞品 |
| rrweb / DOM 镜像 | 一期不做 UI 树重建（T1）；回放能力不等于双向可操作的应用远程化 |
| Electron OSR | 需要目标应用主动接入；第三方应用不可施加 |
| Playwright Electron | 测试/自动化用途，不是远程显示框架 |
| 完整 RDP 服务端 | 工程目标是另一条产品线（`01` §4） |

## 4. 合规与边界提醒

| 项 | 说明 |
|---|---|
| Claude 使用条款 | 本方案是"人工在远端真实客户端上操作"的远程化，**不是**把订阅转成 API，也不是自动化访问。控制方式与自动化抓取有本质区别，实施时应保持这一点（例如不实现"程序自动驱动界面抓取回答"的功能） |
| 不改包不注入 | 一期明确不改官方应用、不注入脚本、不依赖调试端口（T8/T9） |
| 隐私 | 默认不记录画面与输入内容；诊断数据最小化 |
| 安全宣传口径 | 不得宣称"用户只能影响被共享的应用" |

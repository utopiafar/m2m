# 02 架构

## 1. 总体结构

```
┌──────────────────────── 本地 Mac：Viewer.app（原生）────────────────────────┐
│  AppKit 层                                                                  │
│   ├─ 窗口管理（每个远端窗口 ↔ 一个 NSWindow / NSPanel）                      │
│   ├─ 输入与焦点（键鼠采集、焦点路由、修饰键跟踪）                            │
│   ├─ 文本输入（NSTextInputClient：组合、候选窗、提交）                       │
│   └─ 菜单（远端应用菜单入口）                                                │
│  SwiftUI 层                                                                 │
│   └─ 连接、配对、设备管理、诊断面板、权限引导                                 │
│  媒体接收：解码 → 显示层（CAMetalLayer / NSView）                            │
│  桥接层：剪贴板、文件接收、指标上报                                          │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   │
        四条逻辑通道（同一加密会话内，独立队列与优先级）
        ① 窗口状态  ② 媒体画面  ③ 文本/输入  ④ 文件与剪贴板
                                   │
┌─────────────────────────── Relay（第三方中继）──────────────────────────────┐
│  设备注册、会话协调、信令、TURN 转发                                          │
│  不运行 Claude，不解码/转码视频，不解析业务内容                                │
│  （如启用，媒体与数据端到端加密，见 §6）                                      │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   │
┌───────────────────────── 远端 Mac：Host.app（登录用户会话内 Agent）─────────┐
│  应用与窗口注册表（AX 枚举、窗口身份、父子关系、聚焦状态）                    │
│  采集：ScreenCaptureKit（按窗口过滤，GPU 缓冲）                              │
│  编码：VideoToolbox（实时低延迟模式）                                        │
│  输入执行：CGEvent 键盘/鼠标；文本路径见 04-text-input.md                    │
│  AX 状态读取：焦点控件、选区、光标矩形（增量、带版本）                        │
│  适配器：通用 macOS ｜ Electron AX 增强 ｜ Claude 专用规则（可选）            │
│  文件接收：临时目录 + 校验                                                   │
│  权限与撤销：屏幕录制、辅助功能、输入监控                                     │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   │
                          官方 Claude Desktop（不修改）
```

**中央设计原则**：本地决定"窗口放在哪里"，远端决定"应用内容是什么"。只有**尺寸、焦点、关闭/最小化、模态**这些会影响应用行为的操作才同步到远端。

## 2. 进程与运行条件

### Host 运行条件

| 项 | 一期要求 | 说明 |
|---|---|---|
| 用户图形会话 | **已登录**（非登录窗口、非系统级 daemon） | 系统级 Daemon 没有 WindowServer 访问能力，不能运行 GUI 应用 |
| 权限 | 屏幕录制、辅助功能；若需监听原始键盘还需输入监控 | 权限缺失必须显式上报到 Viewer，而不是静默降级 |
| 应用状态 | 由 Host 启动/定位 Claude；Host 崩溃后可恢复 Claude 窗口 | 见 §5 |
| 显示器 | 允许无物理显示器（依赖虚拟显示器方案时）；但"无显示器恢复"属 P6 二期项 | |

### 为什么 Host 必须是 Agent 而非 Daemon

macOS 的系统级 daemon 运行在 bootstrap 中，不具备图形会话上下文，无法操作 GUI 应用窗口。Host 必须以**用户会话内的 LaunchAgent** 形式随登录启动，并保留对 WindowServer 的访问。

### Host 的启动与重启

```
launchd (LaunchAgent)
   └─ Host.app 启动
        ├─ 权限自检（屏幕录制 / 辅助功能）
        ├─ 向 Relay 注册设备
        ├─ 等待配对连接
        └─ 连接建立后 → 定位或启动 Claude
```

Host 崩溃重启后：重建窗口注册表，重新采集，**不重放崩溃前的任何输入事件**（见 §5.3）。

## 3. 模块边界（本地 Viewer）

| 模块 | 职责 | 不该包含 |
|---|---|---|
| `WindowRegistry` | 远端窗口 ID ↔ 本地 `NSWindow` 的映射、父子、模态、标题、内容区几何 | 不解析应用内部控件 |
| `WindowShell` | 本地窗口创建/移动/缩放/最小化；缩放中临时缩放旧画面并在结束后切回清晰画面 | 不做视频解码 |
| `GeometrySync` | 逻辑点/像素/远端布局三套坐标的映射；请求-读回-确认流程 | 不直接改远端像素输出 |
| `TextBridge` | `NSTextInputClient` 实现、组合状态机、候选窗锚点、提交序号 | 不维护远端全文副本（P3） |
| `InputRouter` | 修饰键跟踪、快捷键、鼠标、滚动的优先级路由 | 不把拼音按键逐键发往远端 |
| `MediaPipeline` | 接收、解码、丢帧策略、显示层 | 不做窗口管理 |
| `ClipboardBridge` | 文本/图片双向，防回环 | 不做文件传输 |
| `FileBridge` | 本地选择/拖入 → 传输 → 远端临时目录；进度与清理 | 不做透明文件系统 |
| `SessionState` | 连接状态机、重连、错误呈现、诊断指标 | 不做业务适配 |
| `AppAdapter`(本地侧) | 认证应用清单、降级标识、能力上报展示 | 不含具体应用逻辑 |

## 4. 线程与队列模型

这是本项目的**正确性基础**，不是性能优化项。

### 4.1 远端 Host

| 队列 | 内容 | 约束 |
|---|---|---|
`capture` | ScreenCaptureKit 回调 | 只做格式转换/直传，不做同步 AX 查询
`encode` | 编码提交与输出回调 | **有界队列**；只丢弃尚未编码的过期画面
`input` | 键鼠事件与文本提交 | **可靠有序，不丢**；优先级高于媒体
`ax` | AX 读取与事件订阅 | 独立队列，带版本，过期结果丢弃
`file` | 文件分块传输 | **限速**，不得挤占 `input` 与 `media` 出口

### 4.2 本地 Viewer

| 队列 | 内容 | 约束 |
|---|---|---|
`decode` | 视频解码提交 | 保持有界；重新连接立即请求可解码关键帧
`display` | 显示层更新 | 不与窗口几何操作互相阻塞
`input` | 本地键鼠/组合文本采集 | 本地即时应答（窗口移动、候选窗）不得排队等网络
`ui` | AppKit 主线程 | 窗口创建/移动必须在主线程

### 4.3 硬性规则

1. **媒体快路径不得同步查询 AX 树。** 采集/编码/显示路径上的每一帧都不允许等待 AX。
2. **输入消息不得被文件上传阻塞。** 文件通道独立调度并限速。
3. **可以丢弃未编码的过期画面；不得无视参考依赖丢弃已编码帧。** 后者会造成花屏并触发整帧重传，反而放大延迟。
4. **不确定是否执行成功的操作不得自动重试。** 尤其：点击"发送"、提交文本。
5. **连接丢失时释放所有按下的修饰键。**

## 5. 会话状态机

```
DISCONNECTED
    │ 配对/连接
    ▼
NEGOTIATING ──失败(证书/版本/权限)──► ERROR(可见原因)
    │ 协商完成（能力：媒体格式、适配器清单、文本能力）
    ▼
ACTIVE ◄──────────────┐
    │ 网络中断/超时     │ 重连成功（重新同步状态）
    ▼                  │
RECONNECTING ──────────┘
    │ 超时 / 用户取消
    ▼
SUSPENDED（远端应用保留，不关闭）
```

### 5.1 五个必须区分的语义

本地用户动作 → 远端效果，一期明确定义：

| 本地动作 | 远端效果 | 不得混淆为 |
|---|---|---|
| 关闭远控窗口 | 本地窗口隐藏/销毁，**会话可保留** | 关闭远端应用 |
| 断开会话 | 释放媒体，远端应用继续运行 | 关闭远端应用 |
| 显式"关闭远端窗口" | 向远端发送窗口关闭请求 | 断开连接 |
| 断开后重连 | 重新同步窗口注册表与文本上下文 | 恢复旧输入队列 |
| Host 崩溃重启 | 重建窗口注册表；丢弃旧输入 | 会话无缝续传 |

### 5.2 重连时必须做的事

1. 重新枚举远端窗口，比对本地窗口外壳，**对已消失的远端窗口关闭本地壳**（不得留"僵尸窗口"接收输入）。
2. 丢弃本地尚未确认发出的输入队列（不重放）。
3. 请求可解码关键帧。
4. 重新读取文本上下文；若远端焦点已变化，**清空本地组合文本并提示**，不得继续向旧控件提交。
5. 释放所有修饰键按下的本地状态。

### 5.3 会话身份与窗口身份

- 窗口身份 = `(session_epoch, window_uid, app_pid, app_launch_id)`，**不是**一个永久数字。
- 应用重启后建立新的会话身份；旧身份的输入必须被拒绝。
- 每条输入消息携带 `target_window` 与 `edit_version`（文本相关），不匹配则丢弃并上报。

## 6. 安全模型

| 项 | 一期要求 |
|---|---|
| 设备配对 | 显式配对流程（一次性配对码/密钥交换），非"输个 IP 就连上" |
| 传输 | 端到端加密（媒体 + 数据）；密钥由配对产生并在两端保管 |
| 中继可见性 | Relay 可见连接元数据与信令；业务内容不可见（E2EE）。**不宣称"服务器什么都看不到"** |
| 权限撤销 | 本地可随时撤销设备控制权；远端可随时停止接受控制 |
| 记录 | 默认**不记录画面与输入内容**；诊断日志不含聊天正文 |
| 暴露面 | 调试接口、RDP 端口、AX 检查接口**不得暴露到公网** |
| 共享范围 | 明确：窗口级共享 ≠ 键盘沙箱。画面与鼠标可限定范围，键盘控制仍是整机语义（见 `10-risks-licenses.md`） |

### Tailscreen 式的控制撤销设计值得借鉴

一期应实现"控制撤销"的独立路径：即使在媒体链路异常时，撤销指令也必须能生效（走独立低带宽信令通道）。

## 7. 能力上报与降级

连接协商时，Host 上报**能力清单**，Viewer 据此决定界面行为：

```json
{
  "capabilities": {
    "media": { "codecs": ["h264"], "max_fps": 60 },
    "text": {
      "ax_available": true,
      "focus_tracking": true,
      "selection_read": true,
      "caret_rect": true,
      "composition_support": false
    },
    "adapters": ["generic-macos", "electron-ax", "claude"],
    "apps": [
      { "bundle_id": "com.anthropic.claudefordesktop", "certified": true, "input_mode": "local-ime" }
    ]
  }
}
```

**规则**：

- AX 读取失败 **不得**导致窗口无法显示（画面 + 鼠标仍可用）。
- 但 AX 失败时 **不得**宣称"原生中文输入已达标"。Viewer 必须把该应用标为"降级模式"。
- 能力清单是可协商的**声明**，不是承诺；实际行为由 G1 验证结果决定。

## 8. 目录与工程结构（建议）

```
m2m/
├─ apps/
│  ├─ Viewer/            # 本地原生客户端（Swift + AppKit + SwiftUI）
│  ├─ Host/              # 远端宿主（Swift, LaunchAgent）
│  └─ TestApps/          # 可控测试应用（见 06-test-plan.md）
├─ packages/
│  ├─ Protocol/          # 消息定义（Swift，可加 schema 导出）
│  ├─ WindowCore/        # 窗口注册与几何映射（两端共享）
│  ├─ TextBridge/        # 文本输入状态机（两端共享）
│  └─ MediaKit/          # 媒体链路封装
├─ relay/                # 中继部署配置与协议（不承载业务内容）
└─ docs/                 # 本目录
```

拆包的目的不是"架构好看"，而是让 Agent 能在**不启动 GUI**的情况下对 `Protocol` / `WindowCore` / `TextBridge` 做单元测试。GUI 与真机权限相关部分必须由真机验收。

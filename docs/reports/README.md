# 验证报告目录

`06-test-plan.md` §5 定义的四项真机门槛报告写在本目录下：

| 文件 | 门槛 | 必须包含 |
|---|---|---|
| `G1-text.md` | 文本输入闭环 | T-CN-01…16 的三态结果（通过/失败/未执行）、caret rect 可获得性结论、**选词 Enter 是否误发送**的直接证据、录屏路径 |
| `G2-window.md` | 窗口完整性 | T-WIN-01…15 三态结果、弹窗/子窗口处理结论、缩放后真实重排的证据 |
| `G3-perf.md` | 性能基线 | 采集/编码/传输/解码/显示/排队分段耗时、端到端中位数与较差值、弱网矩阵结果、原始数据文件路径 |
| `G4-recovery.md` | 恢复与错误输入 | T-REC-01…10 三态结果；特别记录"结果未确认"场景的行为 |

## 报告格式要求

1. **三态结果**：通过 / 失败 / 未执行。**不允许"部分通过"。**
2. 每条失败项必须给出**归因分类**：测试对象问题 / 协议问题 / 输入法问题 / 环境问题。
3. 性能数据必须附**原始文件**（CSV / JSON），不能只给结论数字。
4. 每条结论必须能追溯到具体测试步骤与时间。
5. 结论措辞遵守 `09-agent-rules.md` §5。

## 门槛未过时的处理

**不得"先继续做，后面再补"。** G1 未过 → Claude 不得进入认证列表（或必须开发专用适配器后再评），并按 `11-open-decisions.md` §三 触发相应的产品决策。

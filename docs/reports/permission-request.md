# 权限申请清单（需要你这边批准）

截至本文件生成时，自动化环境下已探明的权限现状如下。**下面第 2 项是唯一阻塞项**，
它挡住的正是本项目最关键的一条验证（G1：真实中文输入闭环）。

| # | 权限 | 当前状态 | 阻塞什么 | 是否需要你操作 |
|---|---|---|---|---|
| 1 | **屏幕录制** | ✅ 已授权 | — | 否 |
| 2 | **辅助功能** | ❌ **未授权** | 真实 AX 窗口信息、CGEvent 输入注入、**真实插入点（光标）位置读取** | **需要** |
| 3 | 输入监控 | ❌ 被拒绝 | 仅"全局快捷键捕获"（应用不在前台时也能响应）。**不影响核心功能** | 可选 |

---

## 1. 为什么需要「辅助功能」权限

它解锁的是**真实目标应用**上的三件事，缺一不可：

| 能力 | 现状（无权限） | 授权后 |
|---|---|---|
| 改远端窗口尺寸 | 真实采集下改不了尺寸（会如实报"受约束"） | 缩放窗口 → 远端真实重新排版 |
| 注入鼠标/键盘事件 | 只能走代理通道（demo 应用可用，真实第三方应用不行） | 能操作任意真实应用 |
| 读取插入点矩形 | **读不到**，本地输入法候选窗无法跟随光标 | 候选窗贴住光标，达到 P2 的"认证应用"标准 |

第三项是关键：按项目已定的规则（`docs/07-decisions.md` 的 P2），
**读不到插入点时不允许把该应用标注为「本地输入法体验达标」**。
所以在此之前，对真实第三方应用的输入法结论只能是"待验证"，而不是"通过"。

## 2. 怎么授权

系统设置 → 隐私与安全性 → **辅助功能** → 打开开关，把运行它的终端应用加进去。

需要授权的对象是**启动 `m2mhost` 的那个终端/IDE**（权限随父进程继承）：

- 如果你用 Terminal.app 跑：授权 `/Applications/Utilities/Terminal.app`
- 如果用 iTerm2：授权 `/Applications/iTerm.app`
- 如果用 ZCode / VS Code 的终端：授权对应的 IDE 应用

授权后**必须重启该应用**（macOS 对辅助功能权限的授予只在进程启动时读取）。

授权完成后运行下面的命令自查，应当看到"辅助功能 … 已授权"：

```bash
.build/debug/m2mctl env        # 会打印当前权限状态
```

## 3. 授权后我会立刻补做的验证

这些用例的代码**已经写好并有对应实现**，只差权限就能跑：

| 编号 | 验证内容 | 判据 |
|---|---|---|
| G1-a | 真实应用的插入点读取 | `AXTextContextProvider.caretRectCapability == .fullLocalIME` |
| G1-b | 候选窗跟随插入点 | `firstRect` 返回的屏幕矩形随光标移动、换行、滚动而正确变化 |
| G1-c | 真实中文输入到真实应用 | 用系统输入法逐键输入，文字正确出现在目标应用，且**选词 Enter 不触发发送** |
| G1-d | 真实缩放重新排版 | 拖拽缩放后目标应用真实重新排版，松手后文字恢复清晰 |
| T-IN-01 | 真实鼠标点击位置映射 | 缩放后点击位置仍准确（几何映射在真实 DPI 下正确） |
| T-REC-08 | 撤销控制即时生效 | 撤销后立刻停止接受输入 |

> ⚠️ 即使授权，**中文输入法的手感与候选窗视觉位置仍需你本人确认**——
> 自动化能断言坐标与状态，不能断言"用起来别扭不别扭"。
> 授权后建议跑一次 `.build/debug/m2mctl up` 亲手试。

## 4. 可选：输入监控权限

只有在你需要"应用不在前台时也能响应快捷键"时才需要。
它的影响面很小，缺失时程序会在 HUD 里提示，不影响窗口内输入。

申请方式同上：系统设置 → 隐私与安全性 → **输入监控**。

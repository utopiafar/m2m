# 09 Coding Agent 工程规则

本文件是给 AI Coding Agent 的**强制规则**。规则来自项目调研中反复强调的真实故障类型，不是通用最佳实践。

---

## 1. 绝对禁止（正确性红线）

| 编号 | 禁止 | 原因 |
|---|---|---|
| **A1** | 在"执行结果不明"时自动重试输入（点击发送、文本提交） | 会产生重复发送/重复文本 |
| **A2** | 用"每次覆盖整个输入框的 `AXValue`"实现文本输入 | 破坏组合、选区、撤销；属于伪输入法支持 |
| **A3** | 把同一段文字既作为文本提交、又作为按键发送 | 重复输入 |
| **A4** | 无视参考依赖丢弃**已编码**视频帧 | 花屏 + 整帧重传，延迟反而放大 |
| **A5** | 在媒体快路径（采集/编码/显示）内同步查询 AX 树 | 每帧阻塞，延迟累积 |
| **A6** | 把未识别窗口/弹窗自动退化为"共享整个远端桌面" | 违背共享范围预期 |
| **A7** | 断线重连后重放离线期间的输入队列 | 错窗口输入、重复操作 |
| **A8** | 在连接丢失时不释放已按下的修饰键 | Cmd 卡住，后续输入语义全错 |
| **A9** | 持久化 `window_uid` 并跨应用重启复用 | 旧身份输入会打到新窗口 |
| **A10** | 把调试端口 / AX 检查接口暴露到公网 | 安全面 |
| **A11** | 在诊断日志中写入聊天正文或输入内容 | 隐私 |
| **A12** | 用程序化 setValue 通过"输入法测试" | 与真实 IME 路径不同，等于没测 |
| **A13** | 只因为"Electron 一般支持辅助功能"就断言 Claude 可用 | 未验证即声明 |

## 2. 必须遵守的实现规则

### 2.1 输入与文本

| 编号 | 规则 |
|---|---|
| B1 | 文本提交必须携带 `edit_version` + `commit_seq`；不匹配则拒绝执行并回报，由用户决定是否重发 |
| B2 | 组合期间（`NSTextInputClient.hasMarkedText() == true`）不得向远端发送任何按键 |
| B3 | 组合期间用户点击别处：**先取消组合**，再切换焦点 |
| B4 | `TextContextInvalidated` 到达时立即清空本地组合区，丢弃未提交的组合文本并提示 |
| B5 | 每条输入消息必须携带 `target_window`；不匹配则丢弃并上报 |
| B6 | 候选窗位置必须来自远端 caret rect，或按 `04` §4.3 的显式降级链路；**不得把"最后点击位置"当作正常路径** |
| B7 | 收到 `status=unknown` 时，界面不得显示"已发送"；必须显示"结果未确认" |

### 2.2 媒体

| 编号 | 规则 |
|---|---|
| B8 | 采集/编码/接收队列必须有界 |
| B9 | 可以丢弃未编码的过期画面；丢弃策略需区分"未编码"与"已编码" |
| B10 | 不要同时维护两套编码（先把原始帧交给 SDK，或明确自管 VideoToolbox 链路，**不得双重编码**） |
| B11 | 重连后立即请求关键帧，不等待周期性 IIDR |
| B12 | 窗口最小化时停止编码并发 `paused`，不持续发送同一帧 |

### 2.3 窗口与几何

| 编号 | 规则 |
|---|---|
| B13 | 画面帧与几何信息的 `layout_version` 必须一致；不一致则丢弃该帧而不是显示错区域 |
| B14 | 本地缩放是"请求"，远端读回是"事实"；本地必须接受 `actual_content_size` |
| B15 | 同一窗口的 resize 请求合并到约 10 Hz，只发最新 |
| B16 | 本地移动窗口**不**驱动远端移动 |
| B17 | 关闭语义必须区分：隐藏本地壳 / 断开会话 / 关闭远端窗口 |

### 2.4 会话与恢复

| 编号 | 规则 |
|---|---|
| B18 | 重连时比对远端窗口注册表与本地壳，关闭已消失远端窗口对应的本地壳 |
| B19 | 重连时重新读取文本上下文；远端焦点已变化则清空本地组合 |
| B20 | 撤销控制指令走独立低带宽通道，即使媒体链路异常也必须能生效 |

### 2.5 安全

| 编号 | 规则 |
|---|---|
| B21 | 媒体与数据端到端加密；密钥由配对产生 |
| B22 | 诊断日志不含内容（画面、输入、聊天正文、剪贴板内容） |
| B23 | 能力上报是声明而非承诺；界面必须能表达"降级模式" |

## 3. 代码结构规则

| 编号 | 规则 |
|---|---|
| C1 | 协议消息定义集中在 `packages/Protocol`，可导出 schema；不得散落在各模块中各自序列化 |
| C2 | `WindowCore` / `TextBridge` 必须能在**不启动 GUI** 的情况下单元测试 |
| C3 | 每个平台相关的调用（AX、ScreenCaptureKit、VideoToolbox、CGEvent）必须被封装在薄适配层内，便于替换与 mock |
| C4 | 不得在状态机中引入"隐含的自动重试"；所有重试必须是显式、可配置、有上限的 |
| C5 | 时间敏感逻辑不得依赖两端时钟同步 |

## 4. Agent 的测试边界

### 可以自动做

- 单元测试：协议编解码、状态机迁移、几何映射、合并/丢弃策略。
- 用可控测试 App 的**只读断言接口**验证状态。
- 弱网注入下的日志采集、指标聚合、报告生成。
- 回归运行与指标对比。

### 必须人工/真机做

- 真实系统输入法的组合、候选窗、选词交互。
- 视觉判断：候选窗是否贴近插入点、文字是否清晰。
- 权限授予与首次跨机器配对。
- 应用特定行为的判断（Claude 的特殊窗口、菜单、剪贴板交互）。

### 硬性约束

> **同一时刻只允许一个测试执行者控制同一个 Mac 图形会话。**

多个 Agent 同时操作同一台 Mac 会抢焦点，制造大量假故障。执行测试时必须有独占锁（例如一个进程锁文件或显式的测试租约）。

## 5. 报告规范

**Agent 不得使用以下表述**，除非附有对应的真机测试报告文件路径与截图：

| 禁止表述 | 应改为 |
|---|---|
| "已支持中文输入法" | "T-CN-xx 通过（见 reports/G1-text.md）" |
| "Claude 兼容" | "Claude 在 M0 场景下的 xxx 已通过，yyy 未验证" |
| "延迟低" | "在 <设备>、<尺寸>、<网络条件> 下测得端到端中位数 xx ms" |
| "参考了某项目的实现" | 明确写"参考设计"或"复用代码（许可证 X）"，两者不能混用 |

**每个完成的里程碑必须交付**：

1. 测试用例执行结果（通过/失败/未执行三态，不允许"部分通过"）。
2. 未通过项的归因（是测试对象问题、协议问题，还是输入法问题）。
3. 指标数据原始文件。
4. 更新后的 `docs/reports/G*.md`。

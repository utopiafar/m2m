# 01 总览：目标、范围、术语

## 1. 背景

要解决的问题不是"远程桌面"，而是：

> 我在本地 Mac 上，希望**像操作一个本地 App** 那样操作远端 Mac 上的官方 Claude 桌面客户端——独立窗口、本地输入法（中文）、本地快捷键，不先进入一个远程桌面。

已确认的既有条件（来自前期调研，不再重复确认）：

- **Mac→Mac**，两端均为 Apple Silicon。
- **允许第三方中继服务器**（不要求纯直连）。
- **远端可无人使用**，可以把图形会话交给单一控制者独占。
- 中文输入法体验与性能是**首要需求**，不是后期兼容项。
- 目标是第三方应用（官方 Claude），**不改包、不注入、不依赖调试端口**。

## 2. 一层一层的"像原生"

"像原生"必须拆成可以独立验收的层，否则无法界定完成度。

| 层 | 一期目标 | 是否受网络 RTT 约束 |
|---|---|---|
| 窗口外壳：移动、缩放外框、最小化、切换、与本地窗口混排 | 完全本地处理，**不等待远端** | 否 |
| 本地光标、窗口边框反馈 | 本地处理 | 否 |
| 中文输入法：拼音组合、候选窗、选词、翻页、退格 | **本地处理**，使用本地词库与输入法 | 否 |
| 文字提交到远端编辑控件 | 一次通信后生效 | 是 |
| 远端内容重新排版（缩放后） | 远端处理并回传 | 是 |
| 点击远端按钮、滚动、内部文本选择 | 远端执行并回传 | 是 |
| 剪贴板、文件 | 显式桥接 | 是 |

**核心工程承诺**：第一、二、三行必须与网络质量无关。第四行以后不可避免受 RTT 影响（见 `05-media-performance.md` 的延迟分解模型）。

**核心工程禁止**：不得把"拖动窗口时本地放大旧画面"当作缩放已实现；不得把"能打出『你好』"当作中文输入已实现。

## 3. 一期范围（In Scope）

1. Mac→Mac，单一控制者，单一图形会话。
2. **通用窗口远程化内核**：窗口注册、窗口画面流、窗口几何与焦点同步。
3. **本地中文输入桥**：本地组合 + 候选窗跟随光标 + 提交到远端编辑控件。
4. **本地原生 Viewer**：AppKit 管窗口与输入，SwiftUI 管设置与连接界面。
5. **媒体链路**：ScreenCaptureKit 采集 → 硬件编码 → WebRTC 传输（含 TURN）→ 硬件解码 → 本地显示。
6. **剪贴板**：文本与图片，双向。
7. **文件桥接**：本地选择/拖入文件 → 显式传输到远端临时目录 → 通过远端应用自身的文件选择流程使用。
8. **应用适配接口**：小型、类型明确的适配器（Claude 适配器 + 通用 macOS 适配 + Electron AX 增强）。
9. **安全基线**：设备配对、端到端加密、可撤销控制、默认不记录画面与输入内容。

### 认证应用清单（一期）

"认证应用"= 通过一期兼容性验收、可宣称"本地输入法体验"的**真实目标应用**。测试用的自建 App 不属于认证清单，它们是验证手段（见 `06-test-plan.md` §2.1）。

| 应用 | 类型 | 一期要求 |
|---|---|---|
| 官方 Claude Desktop | Electron + 原生能力扩展 | **必须达到本地输入法体验**（见 P2） |

未在清单内的应用（含自建测试 App 之外的一切应用）：允许连接与显示，但必须**明确标识为"降级模式"**，不得声称同等支持（见 `04-text-input.md`）。

### 一期测试对象（非认证清单）

按 P1 的锁定值，除 Claude 外还需两个自建/对照测试对象，用于把"通用链路问题"与"应用特有问题"分开归因：

| 测试对象 | 类型 | 作用 |
|---|---|---|
| `TestApp-Native`（自建） | AppKit | 确认通用链路对原生控件成立；提供可自动断言的状态读取接口 |
| `TestApp-Electron`（自建） | Electron | 适配接口的第二样本 + 压力测试（虚拟滚动、`contenteditable`） |

## 4. 非目标（Out of Scope，一期明确不做）

| 不做 | 原因 |
|---|---|
| 完整 UI 树重建 / 把 Claude 的按钮做成本地原生控件 | AX 树会省略实现细节，不是完整视图描述；成本与维护随应用更新而爆炸 |
| DOM 镜像 / rrweb 式重建 | 看起来一样 ≠ 能独立工作；事件、IPC、会话能力不会一起迁移 |
| 改包、注入脚本、依赖 Chromium 调试端口作为运行前提 | 版本脆弱、安全面大、属于第三方应用逆向边界之外的用法 |
| 完整微软 RDP 协议兼容（让 Windows App 直连 Mac 服务端） | 工程目标是另一条产品线；只借鉴其分层设计 |
| 任意 Mac App 通用的控件级原生体验 | 范围不可控，改为"通用内核 + 有限认证应用" |
| 把整个远端编辑器搬到本地执行（长文本选区、富文本、撤销历史本地化） | 属于另一条产品路线（见 P3） |
| 多人并发操作同一远端 Mac 的不同窗口 | 单用户独占会话模型 |
| 系统音频、麦克风双向音频 | 按 P8，一期不承诺；需要时单独立项 |
| 首版开机解锁、FileVault 解密、无显示器/合盖恢复 | 与"已登录会话内恢复"是不同问题（见 P6、`02-architecture.md`） |
| 脚本市场 / 动态插件平台 / 完整 UI 语义协议 | 见 T9 |

## 5. 术语表

| 术语 | 含义 |
|---|---|
| **远端 / Host** | 运行官方 Claude 与 Host 程序的那台 Mac |
| **本地 / Viewer** | 你面前这台 Mac，运行本地原生播放器 |
| **Relay** | 三方中继服务器：负责设备连接与会话协调、转发媒体与控制数据。**不运行 Claude，不做视频转码。** |
| **窗口外壳（shell）** | 本地 `NSWindow`，承载远端窗口的画面，几何由本地决定 |
| **窗口画布 / 图集（atlas）** | 远端按固定布局排列窗口的采集区域；一期默认**不使用**，见 T5 |
| **AX** | macOS Accessibility（辅助功能接口） |
| **组合文本（marked text）** | 输入法尚未确认的拼音/候选文本，区别于已提交文字 |
| **文本通道** | 传递编辑上下文（焦点控件、光标、选区、组合、提交）的逻辑通道，对应微软 MS-RDPETXT 的角色 |
| **认证应用** | 通过一期兼容性验收、可宣称"本地输入法体验"的应用 |
| **降级模式** | 未认证应用的运行方式：可用远端输入法或简单文本注入，界面须标识 |
| **G1–G4** | 四项真机验证门槛，见 `07-decisions.md` |
| **T1–T10 / P1–P10** | 技术与产品决策编号，见 `07-decisions.md` |

## 6. 一期"完成"的定义

一期完成 = 以下全部成立，且由 `06-test-plan.md` 的测试用例证明：

1. 远端 Claude 主窗口在本地以独立 `NSWindow` 出现，**不显示远端桌面**，可与本地 App 混排。
2. 在远端 Claude 输入框中，用本地输入法连续输入中文：组合与候选窗在本地即时响应，候选窗位置跟随远端插入点；中英混输、换行、选区替换、组合中退格、撤销全部正确；**选词 Enter 不会误触发发送**。
3. 本地缩放 Claude 窗口后，远端重新排版，停止拖动后文字**恢复清晰**（不是长期放大旧画面）。
4. 弹窗、设置窗口、右键菜单、文件对话框在主窗口附近正确呈现，父子与模态关系正确。
5. 剪贴板文本/图片双向可用；文件可显式上传并在远端 Claude 的文件选择流程中使用。
6. 断网/重连后：远端应用保留、不重放旧点击、不重复发送、不残留按下的修饰键、文字不写入错误窗口。
7. G1–G4 四项门槛的报告齐备，性能数据为在固定设备与固定画质下的实测值。

## 7. 与调研结论的对应关系

| 调研结论 | 在本方案中的落点 |
|---|---|
| 不做 UI 树重建，画面为主、AX 为辅 | T1、`02-architecture.md` §模块 |
| 本地输入法是可实现的，有 Citrix / 微软 Windows App 先例 | `04-text-input.md` 全篇 |
| 最值得复制微软的是"三条链路"分层 | `03-protocol.md` §通道划分 |
| 性能关键在排队与分层，不在峰值帧率 | `05-media-performance.md` §排队控制 |
| 不默认 fork Transom，也不自研 RDP | `10-risks-licenses.md` §可复用清单、T3 |
| 许可证边界影响复用路线 | `10-risks-licenses.md`、P9 |

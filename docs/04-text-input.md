# 04 文本输入桥（一期核心）

本项目的成败主要落在这一份文档上。调研结论明确：**中文输入法可以做得非常接近本地，但必须做专门的输入桥，不能靠"转发按键 + 视频画面回传候选窗"。**

---

## 1. 目标与非目标

### 目标

| 体验 | 要求 |
|---|---|
| 拼音组合 | 按 `n i h a o` 时，组合文本与候选窗**在本地即时出现**，不经网络 |
| 候选窗位置 | 跟随远端插入点（插入点矩形来自远端，本地做坐标映射）；滚动、换行、缩放后仍正确 |
| 候选词库 | 使用**本地**输入法与词库 |
| 选词确认 | `Enter` / 空格 / 数字键 / 方向键在组合期间**先交给本地输入法**，绝不误触发远端"发送" |
| 提交 | 确认文字后，向远端编辑控件提交**一次**编辑操作 |
| 中英混输 | 组合与非组合状态切换正确，无重复、无丢字 |
| 选区替换 | 有选区时提交替换选区 |
| 组合中退格 | 退格作用于组合文本，不删除远端已提交文字 |
| 撤销 | 远端编辑历史保持可用（不破坏远端 Undo 栈） |

### 非目标（P3 锁定）

- **不把远端编辑器搬到本地执行。** 光标移动、长文选区、富文本、撤销历史最终仍属于远端 App。
- 不维护远端全文副本。
- 不做"每次覆盖整个输入框的 AXValue"式伪输入法支持。

> 这条界线的意义：把"中文输入法像本地"和"整个编辑器本地化"分开，否则范围会无意中扩大一倍以上。

---

## 2. 为什么不走"逐键转发"

两种方式的差别是本项目的技术前提：

```
❌ 不作为主方案（仅作兼容性回退）
本地按 n、i、h、a、o
  → 每次按键传到远端
  → 远端输入法组词、显示候选框
  → 候选框画面传回本地

✅ 主方案
本地按 n、i、h、a、o
  → 本地输入法即时组词、本地候选窗
  → 本地选词"你好"
  → 向远端提交一次文本编辑
  → 远端在插入点插入"你好"
```

**行业先例（证明可行，不证明已实现）**：

- Citrix Workspace for Mac 明确支持客户端输入法（客户端组词，服务端接收）。
- 微软 Windows App for macOS 明确支持使用**本地 macOS 输入法**，要求采用 Unicode 输入模式（区别于发送物理按键的 Scancode 模式）。
- Jump Desktop 在 2026-03-23 更新中改进了 Mac 上中日韩文字的组合输入显示。

这些证明"本地输入法 + 远程应用"是已有产品实现过的能力；**不证明某个开源框架已经在 Claude 上做好**，因此 G1 必须真机验证。

## 3. 数据流

```
本地                                       远端
─────────────────────────────────────────────────────────────
按键 (拼音) 
  │
  ▼
NSTextInputClient
  ├─ setMarkedText("nihao", ...)       ← 本地处理，不联网
  ├─ firstRectForCharacterRange(...)   ← 需要远端插入点位置（见 §4）
  └─ 候选窗（系统输入法窗口）           ← 本地显示，不联网
        │
        ▼ 用户选词
  insertText("你好")
        │
        ├─ 本地立即：更新本地组合区显示（已提交态）
        │
        ▼
  TextCommit { text:"你好", edit_version, commit_seq, intent:insert_text }
        │
        └────────────── 网络 ──────────────►
                                        Host 侧执行（见 §5）
                                        ├─ 优先：真实编辑事件路径
                                        ├─ 其次：AX 支持的写入
                                        └─ 兜底：Unicode 事件
                                        │
                                        ▼
                                  Claude 输入框出现"你好"
                                        │
  TextCommitResult{applied, new_edit_version}
        ◄────────────── 网络 ──────────────
        │
        ▼
  更新本地已知 edit_version；新 TextContext 到达后刷新插入点
```

**关键顺序**：本地候选窗必须先于网络出现。任何"等远端返回再显示候选词"的实现都算未达标。

## 4. 候选窗定位

### 4.1 坐标系与映射链

候选窗位置必须由远端插入点决定，映射链为：

```
远端控件插入点矩形 (AX: caret rect, 窗口局部坐标)
  → 远端窗口 content_rect 内坐标
  → 远端窗口采集像素坐标           [WindowSnapshot.content_rect, content_scale]
  → 媒体流帧坐标                   [layout_version 必须一致]
  → 本地 NSWindow 内容视图坐标      [本地缩放比例]
  → 本地屏幕坐标                    [NSWindow → NSScreen 变换]
  → 交给输入法作为 firstRect 返回值
```

实现要点：

- **必须携带 `layout_version`**：几何与画面来自同一版本；否则会出现候选窗偏移到旧位置。
- 缩放拖动中允许使用最近一次的映射（可接受短暂不精确），**松手后必须重新对齐**。
- 远端 `caret.valid=false` 时（部分控件不提供插入点矩形），降级策略见 §4.3。

### 4.2 触发时机

| 时机 | 行为 |
|---|---|
| 焦点进入新窗口/新控件 | 拉取 `TextContext`，缓存 caret rect |
| 远端 `edit_version` 变化 | 更新 caret rect（增量，带版本） |
| 本地开始组合 | 用最新已知 caret rect；**不阻塞等待新查询**，同时发一次异步刷新 |
| 本地滚动/缩放 | 重新映射（不用旧屏幕坐标）；远端滚动需重新拉取 |
| `caret.valid=false` | 进入降级定位 |

### 4.3 降级链路（必须显式，不得伪装）

```
1. 远端 caret rect（首选）
2. 远端控件 frame + 已知插入比例（次选）
3. 本地最后一次点击位置映射（降级，标注不精确）
4. 窗口中央（最后手段）
```

**硬性要求**：第 3、4 档属于"未达标"状态。若认证应用（Claude）只能停留在第 3 档，则该应用**不得**被标为"本地输入法体验达标"（对应 P2 的另一侧选择）。

调研明确指出：**不能把"最后点击的位置"包装成完整解决方案**——它无法覆盖换行、滚动与光标移动。

## 5. 远端执行路径（Host 侧）

选词确认后，Host 需要把"插入这段文字"作用到真实编辑控件。按优先级尝试：

| 优先级 | 方式 | 说明 | 风险 |
|---|---|---|---|
| 1 | **真实编辑事件路径**：聚焦控件 + 注入等价编辑操作 | 保留组合/选区/撤销语义 | 需要键码→编辑动作映射；IME 组合由本地完成，此处只提交结果文本 |
| 2 | **AX 支持的写入**（若控件声明可写） | `AXValue` 写入 + 更新选区 | **不得整框覆盖**；只允许受控的插入/替换，且必须验证选区语义 |
| 3 | **Unicode 事件**（`CGEvent` 携带字符串） | 兜底 | Apple 明确提示：**应用框架可能忽略事件中的 Unicode，自行按虚拟键码解释**。必须逐应用验证 |

**禁止**：

- 用"每次覆盖整个输入框的 AXValue"冒充输入法支持（破坏组合、选区、撤销）。
- 在 `status=unknown` 后自动重试。
- 在 `edit_version` 不匹配时强行写入。

### 5.1 各路径的适用性与验证要求

| 路径 | 何时可用 | 必须验证的内容 |
|---|---|---|
| 编辑事件路径 | 控件为真正可编辑文本控件 | 中文/英文/换行/选区替换/撤销 |
| AX 写入 | 控件 `AXValue` 可写且选区可设 | 插入后远端 Undo 是否可用；是否触发应用校验 |
| Unicode 事件 | 控件接受带 unicode 的按键事件 | 是否重复字符、是否被忽略、是否触发快捷键 |

## 6. 本地状态机

```text
        ┌──────────────┐
        │  NO_CONTEXT  │  未获得远端可编辑上下文
        └──────┬───────┘
               │ 收到有效 TextContext
               ▼
        ┌──────────────┐   焦点/窗口变化
        │    IDLE      │◄──────────────┐
        └──────┬───────┘                │
               │ 输入法产生组合          │ TextContextInvalidated
               ▼                        │
        ┌──────────────┐                │
        │  COMPOSING   │────────────────┤
        │ (marked text)│  取消组合       │
        └──────┬───────┘                │
               │ 用户选词/确认           │
               ▼                        │
        ┌──────────────┐                │
        │  COMMITTING  │  携带          │
        │  等待结果     │  edit_version  │
        └──┬────────┬──┘                │
           │        │                   │
   applied │        │ unknown/rejected  │
           ▼        ▼                   │
     ┌─────────┐  ┌────────────────┐    │
     │  IDLE   │  │ PENDING_UNKNOWN│────┘  拉取新 TextContext 后由用户决定
     │(新版本) │  │ (禁止自动重试)  │
     └─────────┘  └────────────────┘
```

### 6.1 状态规则表

| 规则 | 说明 |
|---|---|
| 组合期间不得发送任何按键到远端 | 除输入法明确放弃组合（Escape、切窗口） |
| 组合期间不得修改遥控焦点 | 用户点击别处 → 先取消组合，再切换焦点 |
| `COMMITTING` 期间新输入 | 排队，或（更保守）禁用输入直到结果返回；**一期选择排队并在超时后转 `PENDING_UNKNOWN`** |
| 进入 `PENDING_UNKNOWN` | 本地不显示"已发送"；显示"结果未确认" |
| `TextContextInvalidated` | 立即清空本地组合区；未提交的组合文本丢弃并提示 |
| 应用重启（`app_launch_id` 变化） | 全部上下文失效；拒绝旧身份输入 |

## 7. 必须通过的中文验收用例（G1 的展开）

调研反复强调：**"能打出『你好』只能证明字符通了。"**

| 编号 | 用例 | 通过标准 |
|---|---|---|
| T-CN-01 | 单字输入 | "你" 正确出现在远端插入点，无重复 |
| T-CN-02 | 词组输入 | "你好世界" 连续输入；候选翻页后选词正确 |
| T-CN-03 | 候选窗位置 | 在输入框首行、末行、多行中部各输入一次，候选窗贴近插入点，**不悬在播放器中央或鼠标位置** |
| T-CN-04 | 中英混输 | `ni hao` → "你好"，空格切换英文 → "hello"，无多余字符 |
| T-CN-05 | 组合中退格 | 组合 "nihao" 中退格至 "nih"，候选同步更新；**远端已提交文字不受影响** |
| T-CN-06 | 选词 Enter 不误发送 | 组合中按 Enter 只完成选词；远端 Claude **不得**发送消息 |
| T-CN-07 | 数字键选词 | 组合中按 `1` 选候选，远端不产生字符 "1" |
| T-CN-08 | 方向键 | 组合中用方向键选择候选，远端文本不位移 |
| T-CN-09 | 选区替换 | 选中远端已有 "abc"，输入 "你好" 替换，结果正确且可撤销 |
| T-CN-10 | 换行 | 本地 Shift+Enter / Enter 正确区分"换行"与"发送"，与远端应用语义一致 |
| T-CN-11 | 撤销 | 提交后远端 Cmd+Z 能撤销该次提交（远端 Undo 栈未被破坏） |
| T-CN-12 | 组合中切窗口 | 组合 "nihao" 未确认时点击另一窗口 → 组合取消，**不得把 "nihao" 提交到任何远端控件** |
| T-CN-13 | 拖动缩放中断 | 组合中拖动窗口 → 候选窗跟随移动；松手后位置正确 |
| T-CN-14 | 断线中断 | 组合中网络断开 → 组合取消并提示；重连后**不得**自动补发 |
| T-CN-15 | 结果不明 | 强制在提交后断网 → 界面显示"结果未确认"；重连后以实际远端状态为准，**无重复文字** |
| T-CN-16 | 长文本粘贴 | 提交 2000 字符，无截断、无乱序、不阻塞后续输入 |

**T-CN-06 与 T-CN-12、T-CN-15 是最高优先级的三条。** 它们分别对应"误发送""错窗口输入""重复发送"三类真实事故。

### 验收命令形式（需在真机、真实输入法下执行）

调研要求：**不能只通过直接设置字符串来"验收"**——AppKit 的组合文本机制与程序化注入不是同一条测试路径。

| 允许 | 不允许 |
|---|---|
| 在远端窗口内用真实系统输入法（拼音）逐键输入 | 用 `AXValue` 直接写入"你好"当作输入法验收通过 |
| 用 `CGEvent` 模拟物理按键序列，配合真实输入法 | 用 Playwright 在 Electron 内直接 setValue 当作 IME 验收 |
| 自动化断言远端输入框内容 + 截图比对 | 只看本地组合区显示 |

## 8. Electron 相关（Claude）

| 项 | 结论 |
|---|---|
| Claude 架构 | Electron + 原生能力扩展（有公开项目记录了官方 macOS 包中的 `app.asar` 与原生模块）；**不假定为纯 AppKit，也不假定 DOM 可直接利用** |
| 首要接入方式 | **系统窗口 + AX**，与原生应用走同一条路 |
| `AXManualAccessibility` | Electron 支持第三方通过该属性启用辅助功能。若初期读不到控件，**先排除权限/进程/启用状态**，再判定覆盖不足 |
| DOM / CDP / rrweb | **不作为一期运行前提**。CDP 的 `imeSetComposition` 等接口可作为后期研究入口，但调试端口不得暴露公网 |
| 离屏渲染（OSR） | 需要应用主动接入，第三方应用不可施加；仅对自有 Electron 应用有意义 |

### Electron 应用的编辑控件特点

| 特点 | 影响 |
|---|---|
| `contenteditable` 而非 `NSTextField` | AX 层级与选区语义与原生不同；撤销栈由 Chromium 管理 |
| 虚拟滚动/长列表 | caret rect 在滚动后需重新拉取 |
| 输入法组合可能由 Chromium 自己处理 | 若远端已有组合状态，本地的 `TextCommit` 需注意不要二次组合 |

**一期判断**：Claude 的输入法适配很可能需要一条**专用适配器**（在通用 AX 之上）。这是 G1 要给出的结论，不能预设成功。

## 9. 性能边界（与 05 的关系）

| 部分 | 是否受网络约束 |
|---|---|
| 拼音组合、候选窗显示、翻页、退格 | **否**——必须纯本地 |
| 候选窗跟随光标（远端滚动/换行后） | 是（需要新的 caret rect） |
| 文字在远端出现的时刻 | 是（一次 RTT） |
| 远端编辑结果回显（画面） | 是（一次 RTT + 编码解码） |

工程目标（待验证，不是承诺）：本地交互反馈 **p95 ≤ 30 ms**（本地窗口操作与组合输入）。

## 10. 一期的明确界线（写进产品定义）

> **认证应用必须达到本地输入法体验；未认证应用降级为远端输入法，并在界面明确标识，不得声称同等支持。**

这条界线的另一种表述（来自 P2）：如果某个应用的 caret rect 读不到、只能靠"最后点击位置"，那就**不允许**它进入认证列表，而不是用一个看起来能用的近似来充数。

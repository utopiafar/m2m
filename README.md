# m2m — Mac→Mac 应用窗口远程化

把另一台 Mac（**远端**）上的应用窗口，以**本地原生窗口**的形式呈现并操作，重点解决**中文输入法体验**。

> **远端应用负责渲染与执行；本地负责独立窗口、输入法与交互接入；画面、窗口状态、文本编辑信息走三条独立链路。**

不是远程桌面，不是 UI 树重建，也不是目标应用的前端复刻。

---

## 这是什么

一个可工作的实现，包含：

| 组件 | 说明 |
|---|---|
| **`M2MCore`** | 协议（四通道 + 紧凑二进制编解码）、窗口注册表与几何映射、文本输入桥状态机、媒体管线、传输层（含弱网模拟）、IPC/中继、平台适配层 |
| **`m2mhost`** | 远端主机代理进程：窗口注册表 → 采集 → 编码 → 经中继发送；接收入口并执行 |
| **`m2mviewer`** | 本地客户端进程：远端窗口 → 独立 `NSWindow`；本地输入法组合与候选窗；鼠标/缩放/快捷键 |
| **`m2mdemo`** | 被代理的目标应用进程（自建 demo，用于验证通用链路） |
| **`m2mctl`** | 编排器：单机四进程隔离运行、场景矩阵、自动生成测试报告 |

## 核心设计取舍

| 决策 | 选择 | 为什么 |
|---|---|---|
| 画面 vs UI 树 | **画面为主，AX 为辅** | AX 树会省略与辅助访问无关的实现细节，不是完整的界面描述；控件级重建的成本随应用更新爆炸 |
| 本地输入法 | **本地组合 + 候选窗跟随远端插入点，确认后提交** | 拼音组合与选词不依赖网络；这是"像原生"的关键 |
| 文本提交与按键 | **严格分成两条路径** | 混用会让同一段文字既被提交又被按键，从而重复输入 |
| 传输 | **原生 WebRTC + TURN（生产）/ UDS 中继（单机）** | 先把延迟测清楚，再决定替换哪一层；不自研 UDP |
| 编码 | **H.264/HEVC 硬件链路为基线** | 合成验证链路使用无损 RLE，使无权限环境也能端到端验证 |
| 界面 | **AppKit 管窗口与输入，SwiftUI 管设置** | 不为了"目标是 Electron"就把客户端也做成 Electron |

## 安全基线

- **设备配对 + 端到端加密**：X25519 密钥协商 + HKDF（配对码作为 PSK 混入）+ ChaChaPoly 分方向加密
- **重放防护**：每个方向独立密钥 + 单调计数器 nonce，重复密文会被拒绝
- **跨连接限速**：错误配对尝试按对端累计，重连无法重置计数
- **未完成握手不外发业务数据**：绝不静默降级为明文

诚实说明：配对码混入 HKDF 的强度介于"纯 PSK"与"完整 PAKE"之间——它对被动窃听提供
机密性、对主动中间人提供认证（中间人不知道配对码就算不出同一把会话密钥），
但配对码本身没有零知识证明。单机 UDS 场景足够；跨公网部署应替换为 PAKE 或证书固定。

## 三条不让步的规则

1. **结果不明时绝不自动重试。** 网络超时导致的"执行结果不明"进入 `pendingUnknown`，由用户决定，避免重复发送。
2. **组合中的按键绝不出本地。** 选词的 Enter 不会变成"发送"；数字/方向/退格同样留在本地。
3. **每一条输入都携带目标窗口与会话代次。** 不匹配即丢弃，避免把文字写进错误的窗口。

## 快速开始

```bash
# 构建
swift build

# 跑单元 + 集成测试（无需任何系统权限）
swift test

# 跑多进程场景矩阵并生成报告
.build/debug/m2mctl selftest

# 启动可交互的四进程演示（能真的看到远端窗口、用本地输入法打中文）
.build/debug/m2mctl up
```

## 单机四进程隔离

```
              m2mctl（编排）
                   │
    ┌──────────┬───┴────┬──────────┐
    ▼          ▼        ▼          ▼
 中继       目标应用   主机代理   本地客户端
 (进程内)   (demo)     (host)     (viewer)
    │          │        │          │
    └──────────┴────────┴──────────┘
       私有运行目录内的 UDS（0700/0600）
```

- 每个角色是**独立进程**，拥有自己的运行子目录与临时目录
- 所有 IPC 走 **Unix 域套接字**，不占用任何网络端口
- 运行目录权限 `0700`、套接字权限 `0600`
- 外部控制（链路条件、目标应用指令）通过进程自己的控制文件，不引入新连接
- 每次运行使用全新的运行目录，退出即清理（`--keep` 可保留排障）

## 权限与降级

实现把**所有平台相关调用**封装在薄适配层后面（规格 C3），因此：

| 环境 | 行为 |
|---|---|
| 无屏幕录制权限 | 使用合成采集源（目标应用内容 → 像素）。采集之后的编码/传输/解码/显示全部真实执行 |
| 无辅助功能权限 | 使用代理输入通道执行输入。真实 `CGEvent` 与 AX 注入路径同样已实现，权限可用时切换 |
| 目标应用无插入点能力 | **明确提示降级**，且不允许被标记为"本地输入法体验达标" |

不兼容场景一律有可见提示，不静默降级。

### 性能基线的关键结论

在注入 RTT 20–250 ms、丢包 3%、带宽 3 Mbps 的条件下：

| 指标 | 实测 |
|---|---|
| **本地交互**（窗口尺寸生效 / 组合更新）p95 | **0.003–0.005 ms**，且在所有链路条件下**完全一致** |
| 文本提交往返 p50 | LAN 20 ms → RTT 80 ms 时 92 ms → RTT 250 ms 时 258 ms |
| 画面帧延迟 p50 | LAN 30 ms → RTT 250 ms 时 158 ms |

**"本地交互与网络无关"这一核心主张得到了实测支持**：端到端延迟随注入的 RTT 单调变化，
而本地交互始终在微秒量级；实现自身的额外开销约为 RTT + 10 ms。

### 尚未验证的部分（诚实边界）

- **真实第三方应用的兼容性没有结论**：按约定用自建 demo 应用验证通用链路。
  换到具体第三方应用的 AX 覆盖率、`contenteditable` 选区语义、编辑器撤销栈，需要按 G1 单独跑。
- **真实窗口操作路径未端到端验证**：缺辅助功能权限。代码已就绪，授权清单见
  [docs/reports/permission-request.md](docs/reports/permission-request.md)。
- **中文输入法手感与候选窗视觉位置必须人工判断**：自动化能断言坐标与状态，不能断言手感。
- **跨境真实线路未测**：所有弱网条件都是单机注入的模型，不是真实家庭宽带的实测。
